# LLM-Wiki 技术债务可执行清单（Tech Debt Checklist）

> 版本：v1.0 ｜ 2026-08-03
> 来源：`docs/ARCHITECTURE.md` §15（17 项已知问题）
> 关联：摄取完善方案 `docs/superpowers/plans/2026-08-02-ingest-pipeline-completion.md`
>
> **使用说明**：本清单把散落的"已知问题"转化为可分配、可验收、可追踪的工作项。
> 优先级（P0–P3）与所属阶段（Phase 0–3）对齐既有方案；"建议负责角色"为逻辑归属，便于单人按子系统分批推进或多人分派。

## 0. 图例

**优先级**
| 级别 | 含义 | SLA |
|------|------|-----|
| 🔴 P0 | 阻塞型，不解决则后续工作无法落地或数据风险 | 立即/本迭代 |
| 🟡 P1 | 质量损伤，影响正确性/可维护性，应在近期解决 | 1–2 迭代内 |
| 🟢 P2 | 工程卫生/可观测性，可延后但不宜长期搁置 |  backlog 排期 |

**工作量**
`S` = 0.5–1 天 ｜ `M` = 1–3 天 ｜ `L` = 3–5 天 ｜ `XL` = >5 天

**建议负责角色**（按子系统归属，非真实团队编制）
| 角色 | 覆盖范围 |
|------|----------|
| 流水线负责人 | run_ingest / 新路径接线 / Generator / Collector |
| 存储与架构负责人 | Schema 迁移 / WikiPage / 溯源 / 版本历史 |
| 基础设施负责人 | 权限 / 队列 / 幂等 / 项目上下文 |
| 治理负责人 | QualityGate/Judge / 标签 / Dedup / NDG |
| 接口与服务端负责人 | HTTP API / MCP / Web UI / 测试覆盖 |
| 图与检索负责人 | 关系图谱 / 混合检索性能 |
| DevEx 工具链负责人 | Lint/Formatter/Type-check / CLI 一致性 / 废弃代码清理 |

## 2. 按阶段汇总（对齐摄取方案）

| 阶段 | 范围 | 包含债务项 | 累计工作量 | 退出标准 |
|------|------|-----------|-----------|----------|
| **Phase 0** 基础修复 | 让系统可安全演进 | #1, #2 | S+S ≈ 1–2 天 | schema 迁移可跑通；权限不再误拒 |
| **Phase 1** 新管线接线 | 让分层验证生效 | #4, #5 | L+S ≈ 3–5 天 | 路径 B 成为生产路径，可 config 回滚 |
| **Phase 2** 质量缺口 | 内容完整性与溯源 | #3, #7, #9, #12 | M+M+S+M ≈ 5–8 天 | 大文档不丢信息；版本/页码级溯源可用；文件夹可批量摄取 |
| **Phase 3** 治理增强 | 让治理真正生效 | #10, #11, #13 | S+M+M ≈ 4–6 天（可并行） | Judge/标签值域/Dedup 三项治理落地 |
| **独立/Backlog** | 卫生与可扩展性 | #6, #8, #14, #15, #16, #17 | 合计 ≈ 10–14 天 | 逐项验收（见主清单） |

> 前 4 个阶段为"接线 + 修复 + 增强"主线（合计约 13–21 天）；独立项可穿插或排期到稳定后。

## 5. 追踪建议

- 每项复用时保留 `#` 编号，便于在 PR/commit 引用（如 `fix(tech-debt#1): register v2.1/v2.2 migrations`）。
- 状态列建议使用：`待启动 / 进行中 / 待验收 / 已解决 / 已搁置`。
- 本清单与 `ARCHITECTURE.md` §15 同步维护：§15 描述"是什么"，本清单描述"怎么做、谁来做、何时算完"。
- 每解决一项，将 §15 对应行状态从"待修/待补/待改…"更新为"已解决（YYYY-MM-DD）"。
