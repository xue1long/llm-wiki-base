# novel-wiki 叙事化写作方法论书籍目标设计

**状态：** 目标设计，尚未进入实现。

## 1. 目标与非目标

`novel-wiki` 是写作知识库，内容同时包含写作教程、写作素材、写作规则、案例和来源关系。目标产物定义为：

> 一套面向写作者的“叙事化写作方法论教程”：用连续的写作任务和案例组织阅读，用 Wiki 页面提供事实、方法和素材，用来源与关系保证可追溯。

目标读者是有写作意图、需要把知识转成写作动作的人。成书后，读者应能沿着“观察与采材 → 主题与结构 → 人物与场景 → 节奏与语言 → 修改与发布”的路径阅读，并在每章完成一个可执行练习。

不承诺把 Wiki 自动变成小说，不承诺 LLM 生成的故事事实真实，不承诺商业成功，也不改变 Wiki 作为知识库源数据的地位。

## 2. 书型定义

书型名称：**叙事化写作方法论教程**。

每章由五层组成：

1. **问题场景**：用真实案例或明确标注的示范场景提出写作问题；示范场景不得伪装成来源事实。
2. **方法解释**：从 Wiki 页面提炼定义、步骤、适用条件和反模式。
3. **案例对照**：引用 Wiki 中的素材、教程案例或反例，解释方法如何工作。
4. **练习与检查**：给出读者可以立即执行的任务和验收清单。
5. **参考关系**：列出来源页面、原始路径、上一章、下一章和相关章节；这些元数据显示在侧栏或脚注，不打断正文。

建议的正文比例是：示范场景 15–25%，方法和案例 50–60%，练习与检查 15–25%。这是排版约束，不是 LLM 自由发挥的目标。

## 3. 目标卷章结构

卷纲按写作者工作流重建，不沿用当前“知识库三性基石、检索层架构、执行层流程”等系统结构。

| 卷 | 读者要解决的问题 | 典型章节 |
|---|---|---|
| 第一卷：素材与观察 | 我该观察什么，怎样把生活变成可写材料 | 观察、体验、阅读、调查、素材筛选 |
| 第二卷：主题与结构 | 素材如何形成主题、冲突和可执行大纲 | 立意、故事问题、结构骨架、情节动力 |
| 第三卷：人物与场景 | 人物为什么行动，场景怎样承载信息和冲突 | 欲望、人物弧、背景、空间、视角、对白 |
| 第四卷：节奏与语言 | 如何让章节推进、转折和表达产生阅读动力 | 节奏、悬念、爽点、描写、句式、收束 |
| 第五卷：修改与发布 | 如何发现问题、验证修改并完成发布 | 反例、审稿、反馈、版权、平台和版本迭代 |

每卷包含 3–6 章；具体章数由页面覆盖和读者任务决定，不再把“10 章”当成书籍永久配置。10 章只表示一次试跑生成数量。

## 4. LLM 使用边界

### 4.1 模式

- `rule_only`：现有规则聚合，默认开启，零外发正文。
- `narrative_draft`：LLM 生成叙事正文草稿，必须显式 `--narrative --use-llm --polish`，只允许 dry-run 或样章发布。
- `narrative`：叙事正文、来源映射、章节关系和质量门全部通过后，使用 `--narrative --apply` 发布；不带 `--apply` 的命令永远只产生 dry-run。
- `encyclopedic`：保留现有显式可选模式，不自动混入叙事正文。

启用正文外发前必须存在 `.llm-wiki/policy.json` 且 `content_export_authorized` 为 `true`。Provider、模型、提示词版本、输入摘要哈希和输出哈希写入 manifest；API key 永不写入产物。

### 4.2 输入与输出契约

LLM 输入只包含当前章节的：章节标题、卷标题、页面标题、页面摘要、内容块、经过项目根目录 allowlist 校验的相对来源路径、页面关系和相邻章节标题。绝对路径、环境变量、密钥和与当前章节无关的页面默认不发送；敏感字段命中阻断规则时先脱敏或拒绝外发。

LLM 必须返回 JSON：

```json
{
  "chapter_id": "v001-c002",
  "sections": [
    {"kind": "narrative_bridge", "heading": "", "body": "", "evidence": []},
    {"kind": "fact_explanation", "heading": "观察不是看见", "body": "", "evidence": ["材料的采集:0"]}
  ],
  "exercise": {"prompt": "", "checks": ["至少记录三种感官信息"]},
  "source_page_ids": ["材料的采集"],
  "chapter_relations": ["v001-c001", "v002-c001"]
}
```

`fact_explanation`、`exercise` 和 `source_page_ids` 必须有证据块或页面引用；`narrative_bridge` 可以没有证据，但必须是通用示范场景，不能添加可被误认为事实的姓名、地点、日期、统计数字或事件。缺字段、引用不存在、引用未覆盖正文、章节 ID 不匹配、截断或超预算都回退到规则版并阻断 `narrative` 发布。

正文渲染不显示内部 block ID；来源以脚注或侧栏显示。LLM 输出的关系只能引用已存在的章节 ID，不能创建新页面或隐式改写 Wiki 关系。

## 5. 来源与章节关系

### 5.1 来源追溯

扫描器读取每个页面 frontmatter 的 `sources`。编译器按章节聚合得到：

```json
{
  "chapter_sources": {
    "v001__v001-c002.md": ["raw/sources/02_进阶技巧/方法论写作过程论.md"]
  },
  "unattributed_page_ids": []
}
```

来源缺失不得伪造为“来源已完整”。`unattributed_page_ids` 必须进入质量门和右侧信息面板；叙事正式发布要求**全 release 页面级**来源覆盖率 ≥ 95%（分母为 outline 中 eligible page_id 数，分子为至少一个合法 `sources` 的 page_id），未覆盖页面只能进入显式挂账清单。

### 5.2 章节关系

由页面关系和 outline assignment 计算章节级边：

```json
{
  "from": "v001-c002",
  "to": "v002-c001",
  "relation_type": "required_by",
  "source_page_id": "材料的采集",
  "target_page_id": "主旨的确立",
  "context": "主旨必须基于材料分析提炼",
  "resolved": true
}
```

关系分为 `previous`、`next`、`supports`、`required_by`、`contrasts`、`related` 和 `unresolved`。`taxonomy_of`、`has_credibility` 等命名空间边继续作为分类元数据，不计入内容关系失败率。正式发布要求非命名空间关系 unresolved 比例 ≤ 5%。

## 6. WebUI 目标体验

Book 页面保留三栏：

- 左侧：按真实卷名分组的目录，显示章名、章节练习状态和来源覆盖标记；
- 中间：叙事正文、方法解释、案例、练习；脚注可跳转到来源；
- 右侧：版本、模式、来源页面、上一章/下一章、相关章节、质量指标和“示范场景”标记。

版本下拉继续选择完整 release。叙事样章进入独立 staging 或 sample 列表，不改变 `CURRENT.json`；只有质量门通过且操作者显式 `--apply` 才能发布正式版本。

## 7. 质量与发布门槛

发布 `narrative` 必须同时满足：

1. outline 覆盖所有 eligible 页面，重复、遗漏和未知 page_id 为硬失败；
2. 每章都有标题、卷归属、至少一个来源或显式 `unattributed` 原因；
3. 来源覆盖率 ≥ 95%，非命名空间关系 unresolved 比例 ≤ 5%；
4. 每个事实段落都有 block/page evidence，叙事桥段明确标记；
5. 每章包含至少一个练习和至少三个可验证检查项；
6. LLM 输出无截断、无非法引用、无章节 ID 越权，且所有章节均为同一模式；
7. 读者任务至少 5 条，任务级通过率 ≥ 80%；
8. release manifest、所有正文、outline、来源索引和关系索引完整性校验通过。`artifact_hashes` 只哈希除 manifest 外的规范化产物，manifest 自身使用单独的 canonical digest，避免自引用。

规则版和叙事版都采用 staged release。任何失败只删除未发布 release，保留上一版 `CURRENT.json` 和可读的规则版。

## 8. 关键风险与处理

| 风险 | 后果 | 处理 |
|---|---|---|
| LLM 把示范场景写成事实 | 读者误信虚构内容 | narrative_bridge 强制标记；事实段落证据绑定 |
| 章节标题与页面主题错位 | 读者预期错误 | outline 生成后做主题一致性检查；不一致阻断发布 |
| 来源字段缺失 | 无法追溯或合规审计失败 | 统计未归属页面；不允许用占位文本冒充来源 |
| 关系目标不存在或跨卷错误 | 导读断裂、死链 | 关系按 page_id/章节 ID 校验；unresolved 超阈值阻断 |
| Provider 超时、限流或模型输出截断 | 半本书或混合风格 | 重试有上限；章节级失败不发布；旧 release 保持可用 |
| 外发内容含敏感或受版权保护文本 | 合规和版权风险 | policy.json 授权、最小输入、输入哈希和审计日志；支持禁用外发 |
| 全量 1749 页导致成本和上下文爆炸 | 预算耗尽、任务长时间占用 | 按卷/章分批；先样章、再小批、最后全量；预算前置检查 |

## 9. 信息盲区

进入正式实现前必须补齐：

- 目标读者是网文作者、一般写作者还是知识管理用户；不同人群需要不同案例和练习；
- “叙事场景”允许的虚构程度，以及是否允许使用合成示范人物；
- `raw/sources` 路径是否都可被当前部署读取，项目外来源如何授权；
- 当前 1749 页中教程、素材、规则、案例的比例和重复率；
- MiniMax 单次输入/输出预算、限流、计费和可接受的单章耗时；
- 章节来源覆盖率和关系解析率的真实基线；
- 全书是否需要保留中英文术语、原文引用和版权声明。

这些数据未补齐前，只允许样章和 dry-run，不允许声称全书叙事化完成。
