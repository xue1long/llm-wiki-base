### 2.1 遗漏模式（跨样本归纳）
1. **截断型遗漏（最大头）**：>8KB 的文档被 `MAX_SOURCE_CHARS=8000` 硬截断，LLM 只见开头片段：
   - 61KB 音频稿：只见 34.7%，"7 大问题答疑"整段（65%）丢失
   - 60KB 讲课实录：只见 23%，人物塑造方法论（45% 行数）丢失
   - 586KB 大文档：只见 1.4%，4 条关键观点 vs 全文
   - 50 篇中 20 篇 >8KB（40%），全部受影响
2. **抽取覆盖不足（独立于截断）**：23KB 误区文档证据表明**实际摄取窗口 >8000 字符**（source 页引用了 8139 字符后的内容），但 38 条误区仍只有 3 条入页——即使内容可见，**单趟 unified 生成的抽取率也低**（清单型文档逐条覆盖 <10%）。此模式同样解释了 5 篇审计中"20 条件丢 2 条/10 问题丢 5 条"的观测。
3. **stub 型遗漏**：LLM 引用但未定义的 slug 被批量建成占位 stub（186-242 字样板），真实内容缺失但页面数虚高（女频大纲 13 entity 中 9 个 stub）。
4. **无遗漏的正面样本**：小文档（<4KB）覆盖完整，source 页忠实提炼。

## 3. 问题清单（按严重度）

### P0 [Critical] 源文件编码检测缺失 → GBK/乱码文件产出垃圾页面
- 现象：全池扫描（1358 篇）发现 **15 篇乱码**（CJK 占比 <25%），且**全部是超大文件**：586KB 文学创作资料（CJK=0）、824KB 玄幻写作资料大全、932KB 网游金钱21条、937KB 千字文、998KB 小说写作教程、1.3MB 圈内网文大全等（>500KB 的文件 100% 是乱码）。
- 根因：Collector 一律按 UTF-8 读文件，无编码探测；GBK 编码（或历史误存）文件解码为乱码 → LLM 收到乱码 → 产出空壳/幻觉页。
- 实证：586KB 文件 reviewer 逆向还原确认是 "GBK→KOI8-U→UTF-8" 双重乱码，真实内容约 10 万汉字（10 个写作教程模块）；该文件产出 5 页几乎全空壳，覆盖度 1/5。
- 影响：这批超大文件恰好是素材库中信息量最大的文档，全部不可用。

### P1 [Critical] 大文档 8000 字符硬截断 → 系统性内容遗漏
- 现象：>8KB 文档仅前 8000 字符（清洗后）送 LLM，后文全部丢弃。50 篇中 20 篇（40%）受影响；61KB 音频稿仅见 34.7%、60KB 讲课实录仅见 23%（人物塑造方法论约 45% 行数丢失）。
- 根因：`MAX_SOURCE_CHARS = 8000`（generator.py），为防 CPU Ollama 超时 + 页面爆炸而设，无分块机制。
- 证据：source 页有 `⚠️ 文档过长` 警告（不静默），但内容损失不可接受。

### P2 [High] 窗口内抽取覆盖不足（独立于截断）
- 现象：23KB 误区文档（38 条清单）仅 3 条入页、32 条遗漏——经核对大部分缺失内容**在摄取窗口内**（截断位置偏移源于清洗前后文本长度差异），即"内容可见但未抽取"。
- 根因：unified 单趟生成的抽取率对清单/条目型文档低（与 5 篇审计中"20 条件丢 2 条/10 问题丢 5 条"同源）；source 页关键观点只列 3-7 条。
- 影响：即使解决截断，清单型文档仍会大量遗漏。

### P3 [High] stub entity 创建激进 → 页面数虚高、占位页泛滥
- 现象：LLM 引用未定义 slug 时批量建占位 stub（写入 entities/ 而非 _stubs/）。女频大纲 15 页中 9 个 stub；148 个 entity 中至少 16 个是文档标题型 stub。
- 根因：stub 创建无置信度/重要性过滤（`RUFLO_MAX_STUBS_PER_INGEST=10` 只限数量不限质量），文档标题本身也被当作实体引用。
- 影响：检索噪音、页面数指标失真、实体页质量被拉低。

### P4 [Medium] id 清洗不完整 → H4 非法 id + H2 坏链接
- 现象：H4 报 6 个非法 id：全角括号（`元素化-（-写作问题-）`、`泰坦-（-普罗米修斯`）与下划线（`大纲示例新人写大纲_7c8873-fdc26bdf`）；H2 报 2 个坏链接（目标 `Aǩ`）。
- 根因：`_sanitize_generated_id` 未剥离全角括号；source 派生 stub id 直接继承文件名中的 `_`（id 字符集不允许下划线）。
- 影响：wiki-spec（id 正则）与产出不一致，链接断裂。

### P5 [Low] sfkey 返回 `finish_reason=length, 0 chars` → 浪费一次重试
- 现象：约 10 次 `LLM response truncated ... 0 chars received`，max_tokens 升级对空内容无效，白白消耗一次重试 + 20-30s。
- 建议：finish_reason=length 且 content 为空时，直接按"瞬时故障"重试（不升级 max_tokens）或换一种方式重试。

### P6 [Info] 模板级冗余
- entity 页「基本信息/简介」内容重复（三江案例）；concept 页「例子」节常填"来源未提供具体例子"（实则有例）。

## 4. 修复优化方案

### S0 [P0] 源文件编码检测与修复
- **目标**：消除 P0——GBK/乱码文件不再产出垃圾页。
- **设计**：
  1. Collector 增加编码探测：严格 UTF-8 解码失败或 CJK 占比 <25% → 尝试 GBK/GB18030 重解；仍乱码则拒收并标记 quarantine（复用既有 quarantine 机制）
  2. **已知乱码链路**（586KB 案例实证）：`UTF-8 解码 → KOI8-U(cp21866) 编码 → GBK(cp936) 解码` 可无损还原（169/171 唯一字符往返）；批量修复 15 篇超大素材时优先尝试该链路，其次 GBK→UTF-8 直转
  3. 提供 CLI 命令扫描并批量修复已知乱码文件；`_tmp_enc_scan_all.py` 的启发式（CJK 占比 + 乱码特征）沉淀为正式工具
- **验证**：586KB 文件修复后重摄取，覆盖度从 1/5 提升；全池扫描 0 乱码
- **改动文件**：`src/pipeline/collector.py`、`src/utils/extract/`、新增 CLI 子命令

### S1 [P0] 大文档分块摄取（map-reduce）+ 抽取覆盖增强
- **目标**：消除 P1（截断型遗漏）+ P2（窗口内抽取率）。
- **设计**：
  1. 按章节/段落切块（复用 `chunker.py`），每块 ≤8000 字符
  2. **Map**：逐块调用 Analyzer（JSON 抽取），产出每块的实体/概念/关键观点
  3. **Reduce**：合并去重（同名实体合并、概念归并）→ 交给 Generator 渲染页面
  4. **抽取覆盖增强**（针对 23KB 误区案例）：Analyzer 对**清单/条目型文档**（数字编号、误区/条件/问题清单）输出完整条目索引，Generator 逐条渲染而非概括；source 页关键观点按清单全量列入
- **改动**：`src/pipeline/ingest.py::generate_ingest` 增加分块分支；`MAX_SOURCE_CHARS` 提升为"单块上限"；Analyzer 提示词增加清单完整度约束
- **验证**：586KB（修复后）/23KB 误区文档复测，覆盖度 ≥80%
- **备选（轻量）**：暂不做 map-reduce，仅把 `MAX_SOURCE_CHARS` 提到 16000-24000 + Analyzer 清单约束；低成本缓解 60%-70% 遗漏

### S2 [P1] stub 治理
- **目标**：消除 P3——占位页泛滥。
- **设计**：
  1. stub 只对高置信引用创建（被 ≥2 个页面引用 或 实体类引用）；文档标题误引用不建 stub（source 页已存在则跳过）
  2. 占位 stub 写入 `_stubs/` 目录并在 frontmatter 标 `grade=C` + `is_immutable`，或干脆只记录引用不建页
  3. 女频大纲式"13 entity 9 stub"场景：限制每篇 stub 数（如 ≤3）+ 超限降级为页内 `related_entities` 列表
- **验证**：女频大纲复测，stub 占比显著下降，覆盖度提升

### S3 [P1] id 清洗扩展
- **目标**：消除 P4——id 合规。
- **改动**：`_sanitize_generated_id`（generator.py）增加：
  - 剥离全角括号 `（）`、书名号 `《》`（替换为 `-` 或删除）
  - 下划线 `_` → `-`（source 派生 id 与 LLM 生成 id 统一）
  - 追加回归测试（含 `元素化-（-写作问题-）`、`xxx_7c8873` 用例）
- **验证**：H4 0 非法、H2 0 坏链接

### S4 [P2] sfkey 空内容截断特判
- **改动**：`_call_with_slot_retry`——`TruncatedResponseError` 且 `len(content)==0` 时，重试不升级 max_tokens（升级无用），提示词改为"输出空内容，请重试"
- **验证**：日志中 0-char 截断不再走 max_tokens 升级路径

### S5 [P2] 页面数护栏 + 大文档分级
- 单文档页面数上限（如 15），超限时在 source 页提示合并；`>30KB` 强制走 S1 分块路径
- 缓解"3.5KB→17 页"类波动

### S6 [P3] 模板冗余修复
- entity 模板「基本信息/简介」合并或提示区分；concept「例子」缺失时用源文档实际例证
