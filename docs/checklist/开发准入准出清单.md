# 开发准入准出清单

> 适配队列：`ruflo-kb`（Python 3.11+，src/ 分层，TDD-per-task）
> 每个阶段开工前/收尾后各自查一遍，未通过不进入下一阶段。

## 〇、需求阶段准入（动手前）

- [ ] 需求目标、输入输出、边界场景已明确
- [ ] 明确本改动属于哪个模块（`src/` 下哪个子包）
- [ ] 明确是否需要新增模块（默认不加，能用现有模块复用就复用）
- [ ] 明确模块交互方式：同步 API / 事件总线（`src/events/`）/ 消息通知
- [ ] 明确**不做的功能**（划清范围）
- [ ] 已产出一份方案笔记（统一放在 `docs/superpowers/plans/`）

## 一、规划阶段准入

- [ ] 拆出最小任务清单，每个任务只改**一个模块**
- [ ] 任务依赖顺序已排定（前置任务在前）
- [ ] 每个任务有明确产出 + 验证方式
- [ ] 是否触碰跨模块调用——确认走 facade re-export（`__init__.py`）而非内部私有路径

## 二、编码阶段准入

- [ ] 契约先行：对外接口 / 类型 / 入参 / 返回值 / 错误结构先定义
- [ ] 是否新增第三方依赖——已评估体积/维护/许可证/安全并记录
- [ ] 参考 SETUP.md 确认测试环境（PYTHONPATH + `--import-mode=importlib`）

## 三、测试阶段准出

- [ ] 新增代码配套了对应测试（TDD：先测试后实现）
- [ ] 测试可单独运行，不依赖完整服务启动
- [ ] `PYTHONPATH=. pytest --import-mode=importlib` 能跑（至少改动受影响目录）
- [ ] 覆盖正常流程 / 异常输入 / 边界 / 回滚场景
- [ ] 重构代码：原有测试全部通过

## 四、自查评审清单（单人评审，逐条过）

- [ ] 无跨模块导入私有内部文件（`service/` `model/` `utils/` 等）
- [ ] 无循环依赖风险
- [ ] 对外接口最小化，未泄露内部实体
- [ ] 异常捕获完备，错误信息规范
- [ ] 无冗余代码、无注释掉的死代码
- [ ] 测试覆盖核心分支
- [ ] 文档同步更新（接口变更 → 更新 wiki-spec / 相关文档）
- [ ] 触摸了 `src/server/` / `src/cli.py` / `src/wiki/` 顶层导入 → 已跑 `serve` + `/health` 验证 lifespan

## 五、提交阶段准出

- [ ] 删除临时调试代码 / console / 硬编码参数
- [ ] 清理注释掉的无效代码
- [ ] commit 格式符合 `type(scope): 描述`（feat/fix/refactor/docs/test/chore）
- [ ] 只 add 本次改动的文件（不用 `git add .`）
- [ ] 全量测试通过（合并至 main 前）

## 迭代红线（任一命中即停）

- [ ] （无）需求不清晰直接编码
- [ ] （无）跳过方案/计划直接写代码
- [ ] （无）破坏模块边界
- [ ] （无）不写测试仅人工验证
- [ ] （无）大量未提交代码滞留本地
- [ ] （无）main 上提交未完成/无法运行的代码
- [ ] （无）接口变更不更新文档
- [ ] （无）超大 PR / 一个 commit 堆大量无关改动
