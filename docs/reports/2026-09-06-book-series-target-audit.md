# 书系目标方案复审记录

**对象：** `docs/superpowers/specs/2026-09-06-novel-wiki-book-series-target.md`、`docs/superpowers/plans/2026-09-06-novel-wiki-book-series-target.md`
**结论：** “三本主教程 + 参考库”比单书五卷更适合当前知识库，但必须先完成页面归属基线和连续样例，不能直接全量编译。

## 第一轮：漏洞清单

### ① 致命缺陷

| 位置 | 问题 | 后果 | 整改 |
|---|---|---|---|
| 书系层级和归属规则 | 假设每个页面都能唯一归属一本书 | 重复页被多次渲染，来源覆盖率和篇幅统计失真 | Task 1 建立 canonical assignment；未知页进入参考库/挂账 |
| 主教程发布 | 假设三本书可以独立完成而无需前置成果 | 单本购买或单独阅读时出现概念断裂 | 每本书声明 `entry_requirements` 和 `exit_artifact`；缺失前置时显示导航提示 |
| 参考库边界 | 假设所有未归属页面适合百科版 | 低质量或敏感内容被“收容”后仍可对外展示 | 参考库同样执行来源、敏感字段和质量门；只是不承担叙事承诺 |

### ② 重大隐患

| 位置 | 问题 | 后果 | 整改 |
|---|---|---|---|
| 跨书关系 | 书间链接目标可能随 outline 版本变化 | 旧 release 出现死链或指向错误章节 | 关系索引绑定 release 版本和稳定 chapter_id，发布前重新解析 |
| 内容重复控制 | 同一方法可能被不同书需要 | 为避免断裂而复制正文，维护和事实校验成本翻倍 | 主书只保留一次解释，其他位置使用摘要 + `supports` 链接 |
| 书系一致性 | 三本书的术语、练习格式可能漂移 | 读者感觉像三套不同教材 | 共享术语表、章节合同和 rubric；每本书独立验收后再做系列验收 |
| 10 章试跑 | 将 10 章跨三本抽样 | 无法验证一条完整学习路径 | 首轮 10 章固定来自《从素材到故事》的连续链 |
| 版本发布 | 一书成功、一书失败时系列状态不明确 | UI 显示“系列已完成”但实际缺书 | 系列 manifest 记录每本书状态，只有全部通过才标记 series release ready |
| 成本与维护 | 三本书分别调用 LLM，重复上下文和术语说明 | token、延迟和费用随书数增加 | 章节输入最小化；共享术语缓存只用于输入，不共享未经校验的正文 |

### ③ 优化疏漏

| 位置 | 问题 | 后果 | 整改 |
|---|---|---|---|
| 参考库定位 | 仅称“可选”，未定义默认 UI 入口 | 用户找不到素材和规则 | 在书系首页固定“主教程/参考库”两类入口 |
| 练习成果 | `exit_artifact` 没有统一格式 | 练习不能跨书接续 | 为主题句、人物卡、章节大纲、修改清单定义最小 JSON/Markdown schema |
| 书名和卷名 | 目前仍是暂定名 | 生成后可能出现标题与内容不符 | Task 2 后做标题—页面主题一致性检查，未通过不得发布 |

## 第二轮：压力测试

| 场景 | 失效链 | 必须观察的结果 |
|---|---|---|
| 页面同时符合两本书 | 双重渲染 → 来源和字数膨胀 → 读者重复阅读 | 只保留一个 canonical 归属，其余为跨书链接 |
| 一章依赖另一书但目标书未发布 | 前置链断裂 → 读者无法完成练习 | 章节显示未发布依赖并阻止“独立完成”标记 |
| 参考库页面被主教程引用后删除 | 脚注死链 → 事实无法追溯 | 删除/归档前检查引用者，或写入不可变快照 |
| 单本 LLM 失败、其他两本成功 | 系列状态错误 → 用户误读完成度 | 单本 staged 失败，series manifest 保持 partial，旧版本可选 |
| outline 版本升级 | 关系 ID 变化 → 旧版本链接漂移 | 旧 release 固定自身 outline 和关系索引，不回写历史产物 |
| 共享术语缓存污染 | 一书的定义覆盖另一书语境 | 缓存只存输入片段和版本，不直接复用生成正文 |
| 参考库含版权/敏感素材 | 主教程合规但参考库泄露 | 参考库也执行外发授权、脱敏和来源审计 |
| 只完成主教程不完成参考库 | 读者任务可做但查证入口缺失 | 发布门记录参考库依赖；缺失时明确标注“参考库未就绪” |

## 复审结论

新方案的主要新增风险集中在“唯一归属、跨书依赖、系列状态”三处，已分别绑定 Task 1、Task 4 和 Task 7。未完成页面基线、连续 10 章样例和书间关系验证前，只能做 dry-run，不能声称书系可发布。
