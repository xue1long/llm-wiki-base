# 叙事化写作方法论目标方案审计记录

**审计对象：** `docs/superpowers/specs/2026-09-06-novel-wiki-narrative-book-design.md` 与 `docs/superpowers/plans/2026-09-06-novel-wiki-narrative-book.md`  
**审计方式：** 独立第三方视角；第一轮全面漏洞审计，第二轮失败路径压力测试。  
**结论：** 方案可作为受控样章和 dry-run 的目标方案；在信息盲区补齐、样章人工验收和质量门实现前，不具备全书正式发布条件。

## 第一轮：问题分级

### ① 致命缺陷

| 漏洞位置 | 隐含假设/问题 | 风险后果 | 整改建议 |
|---|---|---|---|
| 目标书型与卷章结构 | 假设所有页面都能映射到写作工作流 | 教程、素材、规则混编，outline 无法覆盖或产生空章 | 先做页面类型/重复率基线；未知或不适配页面进入挂账，不得硬塞进章节 |
| LLM 正式发布路径 | 假设结构化输出一定能完整返回 | 截断、非法 JSON、章节漏失会生成半本书或混合模式 | 解析、证据、章节 ID、输出完整性全部 fail-closed；失败 release 不得更新 `CURRENT.json` |
| 来源质量门 | 原方案未定义来源覆盖率分母 | 通过率可被空章节或重复页面人为抬高，无法审计 | 固定为全 release eligible page_id 分母，低于 95% 阻断正式发布 |

### ② 重大隐患

| 漏洞位置 | 隐含假设/问题 | 风险后果 | 整改建议 |
|---|---|---|---|
| 叙事桥段 | 假设读者能分辨虚构示范与事实 | 合成姓名、地点、数字被误读为 Wiki 事实 | 强制 `narrative_bridge` 标记；禁止不可追溯事实细节；WebUI 与正文均显示标记 |
| 来源路径外发 | 假设相对/绝对路径都安全 | 文件名、用户名、环境变量或项目外路径泄露 | allowlist 校验，只发送项目根目录相对路径；敏感字段脱敏，命中规则则拒绝外发 |
| 章节关系 | 假设 relation target 永远可解析 | 死链、跨卷错链使阅读顺序和方法依赖失真 | 统一 page_id/alias 解析；namespace 边与内容边分开统计；unresolved 超 5% 阻断 |
| Provider 运行 | 假设 MiniMax 稳定且重试无副作用 | 限流、超时、重复计费、章节风格漂移 | 单章分批、预算预检、同 request hash 最多重试一次；任一章失败不发布 |
| Manifest 完整性 | 假设“所有文件都哈希”可直接实现 | manifest 自哈希自引用，校验不可复现 | `artifact_hashes` 排除 manifest；manifest 用 canonical digest 单独校验 |
| 1749 页规模 | 假设一次全量上下文可控 | 超预算、上下文溢出、长时间占用、成本失控 | 先样章再 3–5 章 pilot，最后全量 dry-run；记录 token、延迟和错误率 |
| 人工验收 | 假设有人按时复核样章和读者任务 | 质量门形式通过但正文不可读 | 把 5 条读者任务和人工签字列为发布前置条件；未完成只能留在 staging |

### ③ 优化疏漏

| 漏洞位置 | 问题 | 风险后果 | 整改建议 |
|---|---|---|---|
| CLI 入口 | `narrative_draft` 与 `narrative` 触发条件容易被误用 | 用户误以为 dry-run 已正式发布 | 固定 `--narrative` 选择模式，带 `--apply` 才发布，命令帮助中写明 |
| 练习设计 | 只规定检查项数量，没有规定难度或答案格式 | 练习看似完整，读者无法自测 | 样章 rubric 增加可观察输出、通过条件和失败示例 |
| 版本切换 | 只说明保留旧 CURRENT，未说明 UI 选择失败时的行为 | 旧版或损坏版显示空白 | 读取 sidecar 先做完整性校验；失败时显示错误和可选的旧 release |
| 信息盲区 | 目标读者、虚构容忍度、预算、版权范围未实测 | 方案方向或成本可能根本不成立 | 在 Task 7 前补齐清单；未补齐不允许全书 apply |

## 隐含假设清单

下列条件必须被验证，标记为“未验证”的不能当作发布依据：

1. **未验证：** `purpose.md` 能明确说明写作方法论目标；否则五卷结构与项目目标冲突。
2. **未验证：** 每个 eligible page_id 可唯一分配到一个章节；重复或未知 ID 会使覆盖率失真。
3. **未验证：** 页面摘要和 block 足以支撑方法解释；不足时只能降级为规则版或挂账。
4. **未验证：** `sources` 是项目根目录可读且具备授权的相对路径。
5. **未验证：** relation target 能由现有 alias/compact 规则稳定解析。
6. **未验证：** MiniMax 配置的模型、配额、延迟和输出上限满足单章预算。
7. **未验证：** 用户允许将正文片段外发给远程 Provider，并接受合成示范场景。
8. **未验证：** 人工审阅者可在发布前执行五条读者任务并记录结果。

## 第二轮：压力测试问题清单

| 失败路径 | 连锁反应 | 方案兜底 | 加固要求 |
|---|---|---|---|
| Provider 首次超时、重试仍超时 | 章节无正文，可能留下临时文件 | 章节级失败，旧 CURRENT 保留 | 重试使用同 request hash；清理未完成 staging，记录错误而不写 API key |
| LLM 返回合法 JSON 但 evidence 不存在 | 正文貌似可读但不可追溯 | 校验拒绝 narrative | 在写 Markdown 前完成 block/page 双重存在性校验 |
| 一章来源缺失、其余章节通过 | 全书覆盖率跌破阈值 | apply 阻断 | 右侧显示挂账页面；允许只导出 draft，不允许伪造来源 |
| 关系目标删除或跨卷错配 | 下一章/相关章节死链 | unresolved 计数并阻断 | 发布前重新扫描 outline assignment，不能复用过期关系缓存 |
| 生成中进程崩溃 | release 目录半成品，CURRENT 可能被误改 | staged release + 原子指针 | 先写临时目录，校验完整后 rename；启动时清理孤儿 staging |
| manifest 损坏或 sidecar 缺失 | WebUI 可能正文空白 | 完整性校验失败 | UI 显示 release 不可读并保留旧版本选择，不静默降级为空 |
| 输入命中敏感/版权规则 | 内容外发造成合规事故 | 脱敏或拒绝外发 | preflight 必须在调用 Provider 前完成；拒绝原因进入审计日志 |
| 全量任务超过预算 | 任务中途被限流或费用失控 | 分批与预算前置检查 | 每批固定上限；达到预算立即停止后续批次且不发布 |

## 复审结论

第一轮发现的 CLI 语义、来源分母、路径外发和 manifest 自引用问题已写入目标设计与实施计划。第二轮的失败路径均以“失败即不更新 `CURRENT.json`、保留旧 release、可定位错误”为最低兜底。仍未解决的部分是信息盲区和真实 MiniMax 成本/质量，必须通过 Task 7 的单章样例与 Task 8 的 3–5 章 pilot 验证后，才可进入全书发布决策。
