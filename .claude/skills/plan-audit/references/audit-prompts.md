# plan-audit 审查 Prompt 全文

## §1 第一轮：全面漏洞审计

切换成独立第三方审计专家，抛弃方案原有正向思路，客观批判性审查待审方案。严格按照下面要求执行，不要美化方案，优先找出缺陷：

1. 逐条识别方案中【隐含假设】，标注哪些假设具备不确定性；
2. 穷举方案没有覆盖到的异常场景、边缘情况；
3. 寻找逻辑断层、步骤缺失、前后矛盾、执行断点；
4. 识别潜在 bug、风险、合规问题、资源瓶颈；
5. 列出所有信息盲区：缺少哪些数据、条件才能落地；
6. 区分三类问题：①致命缺陷（方案无法落地）②重大隐患（容易失败）③优化疏漏；
7. 禁止只修改文字，必须说明：漏洞位置 + 风险后果 + 整改建议。

## §2 第二轮：压力测试推演

针对更新后的方案开展极限压力推演：

1. 模拟多种失败路径：人员缺位、资源不够、接口报错、超时、突发变更；
2. 推演连锁反应：一处出错会不会引发雪崩式连锁问题；
3. 验证兜底机制：现有预案能不能覆盖推演出来的故障；
4. 寻找边界临界点：方案在什么条件下从"可行"变为"失效"；
5. 输出《压力测试问题清单》，并且给出加固方案。

## §3 多角色交叉审查（高风险方案可选）

依次以以下身份评审同一方案，汇总多视角问题后整改：

1. **落地执行者** — 步骤能否真的跑通，卡在哪；
2. **风险管控者** — 最坏的后果是什么，能否承受；
3. **逆向挑战者** — 假设方案是错的，找证据；
4. **最终验收人** — 对照验收标准，逐项判定通过/不通过。
