## 发现的问题

### P0 - 单文件入队缺少advance调用（严重Bug）

**位置**: `src/services/ingest.py:186-190`

**代码分析**:

```python
# 批量入队（正确）- 行259-260
svc = get_default_queue_service()
for _ in range(6):
    svc.advance(project_id=resolved_id)  # ✓ 触发消费

# 单文件入队（错误）- 行186-190
task_id = enqueue_task(...)
if not task_id:
    return {"status": "ignored", ...}
return {"status": "queued", ...}  # ✗ 缺少advance()调用！
```

**影响**:
- 通过API `/projects/{id}/ingest` 提交单个文件后，任务入队但不会被处理
- 只有服务重启时（启动时调用6次advance）才会开始处理
- 这解释了为什么第一轮测试中任务一直处于pending状态

**根因**:
- 开发者只为批量入队添加了advance调用，遗漏了单文件入队路径
- 代码注释 `Subsequent tasks auto-advance via release_in_flight → advance()` 只在任务完成后触发，不能覆盖第一个任务

### P1 - 超时配置不一致

**位置**: `src/pipeline/generator.py`

**发现**:

| 组件 | 超时配置 | 用途 |
|------|----------|------|
| c_grade_handler | 120s | 分级处理 |
| generator (多处) | 600s | LLM生成 |
| ingest._with_llm_timeout | 180s | 分析/生成 |

**问题**:
- 超时值从120s到600s差异很大
- 没有集中配置，散落在各处
- 600s超时过长，可能导致任务卡住10分钟

---

### P2 - 熔断恢复调度时机问题

**位置**: `src/queue/service.py:283-285`

**代码**:
```python
if breaker.state == CircuitState.OPEN:
    self._schedule_recovery_advance()
```

**问题**:
- 熔断器OPEN时调度恢复，但恢复后如果没有外部事件触发，队列会再次停滞
- 依赖 `_schedule_recovery_advance()` 的定时器，但定时器可能在任务完成前就触发

## 修复方案

### 修复1: 单文件入队添加advance调用（立即）

**修改位置**: `src/services/ingest.py:186-190`

**修改前**:
```python
task_id = enqueue_task(source_str, source_type, task_hash, ...)
if not task_id:
    return {"status": "ignored", "taskId": None, "reason": "Duplicate"}
return {"status": "queued", "taskId": task_id, "reason": None}
```

**修改后**:
```python
task_id = enqueue_task(source_str, source_type, task_hash, ...)
if not task_id:
    return {"status": "ignored", "taskId": None, "reason": "Duplicate"}

# Kick off processing if we have capacity
svc = get_default_queue_service()
svc.advance(project_id=resolved_id)

return {"status": "queued", "taskId": task_id, "reason": None}
```

### 修复2: 集中配置超时参数

**新增配置**: `src/config.py` 或 `src/pipeline/config.py`

```python
# Pipeline timeout configuration (seconds)
PIPELINE_TIMEOUTS = {
    "collector_http": 30,      # HTTP fetch
    "analyzer_llm": 180,       # Analysis phase
    "generator_llm": 300,      # Generation phase (reduced from 600)
    "grade_handler": 120,      # Grade processing
    "total_task": 600,         # Whole task timeout

```

### 修复3: 任务完成事件驱动

**目标**: 每个任务完成后自动调度下一个

**修改位置**: `src/pipeline/service.py`

```python
@event_bus.on("task:completed")
async def on_task_completed(payload):
    """Chain-advance after task completion."""
    from ..queue.service import get_default_queue_service
    svc = get_default_queue_service()
    svc.advance()

@event_bus.on("task:failed")
async def on_task_failed(payload):
    """Also advance on failure to process next task."""
    from ..queue.service import get_default_queue_service
    svc = get_default_queue_service()
    svc.advance()
```
